# Actions 硬性限制（用户明确要求）

- 对本任务控制的 GitHub Actions，滚动 60 分钟内最多 10 次，严禁超过。
- 触发前必须读取仓库 Actions 记录，并检查 workflow 运行次数及 job 数；两者均按最多 10 计。失败、取消、跳过及重跑也计入，不能通过切换工作流/分支绕过限制。
- 数据读取失败或无法确认余量时，不启动下一次。
- 禁止 push、PR synchronize、定时自动触发；采用专用标签显式启动。普通提交不应触发实验。
- 同时最多一个实验工作流运行；把多个实验放进同一次 Windows 安装中。
- 每次运行必须保存额度审计日志，禁止自动重跑。达到限额后等待旧记录离开滚动窗口再开始。
- 执行本项目任意后续 Actions 操作之前，必须遵守本文件。

- 新增下一版标签工作流前，必须把上一版标签工作流改为仅 workflow_dispatch，确保一次标签事件不会生成额外的跳过流程。
