# V3.0 — Actual Word native Open split-button menu

The user's task does not require a wrapper. V2.4 already verified Protected
View copy in10cases and V2.5 explicit COM readonly in7cases. Portable startup
was blocked in the unsigned-in test profile and is not declared delivered.

This run tests the exact built-in menu: warm a usable writable Word window,
Ctrl+F12, fill the readonly target filename, click the Open split-button arrow,
then choose Open Read-Only or Open in Protected View. The actual menu and
selection are screenshotted. Require original source path, file attribute and
Document.ReadOnly, page-view3, and real clipboard. Protected View is repeated
with keyboard, mouse, redacted structure, and Chinese text. If native Open
Read-Only succeeds, validate independent repeat/CJK/structure as well.
No launcher code or account credential is used. Privacy remains disabled.
